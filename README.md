# Ghost in the Shell  Hackathon Solution

# **Аанализ графа денежных переводов**  

Репозиторий содержит детерминированный пайплайн для расследовательского анализа графа переводов в KZT.<br>Он объединяет данные об участниках, агрегированных связях и отдельных транзакциях, чтобы:
 - определить роль каждого узла в цепочке движения средств;
 - найти сообщества связанных участников;
 - сформировать список узлов, которые стоит проверить в первую очередь.
<br>
Пайплайн не использует ML или LLM: результаты воспроизводимы при одинаковых входных данных. 

## Что делает пайплайн
 - Строит ориентированный граф из агрегированных переводов.
 - Для каждого узла определяет количество независимых исходных (seed) цепочек, которые к нему пришли.
 - Считает входящие и исходящие суммы, число контрагентов, временную задержку между первым входящим и исходящим переводом, а также betweenness centrality.
 - Разбивает неориентированный граф на сообщества алгоритмом Louvain с фиксированным seed 42.
 - Назначает роль, оценку уверенности и приоритет для ручной проверки. 

## Требования:
 - Python 3.10 или новее;
 - зависимости из requirements.txt;
 - входные файлы Parquet, уже включённые в репозиторий.

python -m pip install --upgrade pip
python -m pip install -r requirements.txt

## Входные данные
Файл	        Назначение	Используемые поля
nodes.parquet	Узлы графа	gid, is_seed, depth
edges.parquet	Агрегированные связи между узлами	src, dst, sum_kzt, n_tx, depth
transactions.parquet	Отдельные переводы для временного анализа	src, dst, date

<br>Где:
gid, src, dst — идентификаторы участников;
is_seed — признак исходного узла известной цепочки;
depth — глубина узла или связи в обходе графа;
sum_kzt — сумма агрегированных переводов в тенге;
n_tx — число переводов, вошедших в агрегированную связь;
date — дата перевода. 

Роли узлов
Роль	Правил   назначения
coordinator	Узел-мост из верхних 10% по betweenness centrality, имеющий не менее трёх входящих и трёх исходящих связей.
consolidator	Получает средства как минимум из трёх независимых seed-цепочек или от трёх и более плательщиков.
distributor	Имеет не менее пяти исходящих и не более двух входящих связей.
transit	Почти полностью передаёт полученные средства дальше (out / in от 0.8 до 1.2) не позднее чем через три дня.
terminal	Имеет входящие, но не имеет исходящих переводов в графе. Для узла на глубине 4 оценка снижена: это может быть граница обхода.
peripheral	Не соответствует правилам выше.
Правила применяются сверху вниз в указанном порядке. Поле role_score — эвристическая оценка уверенности в назначенной роли, а не вероятность.

Интерпретация результатов
priority_score учитывает роль, уверенность классификации, число независимых seed-цепочек, число связей и признак seed-узла. Его следует использовать для очередности проверки, а не как самостоятельное доказательство связи участников. Гипотезы и роли требуют аналитической верификации с учётом внешнего контекста. 

Типичные проблемы

Ошибка чтения Parquet — убедитесь, что nodes.parquet, edges.parquet и transactions.parquet находятся рядом с pipeline.py и не повреждены.
